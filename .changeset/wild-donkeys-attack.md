Issue-tracker integration for the project backlog. Connect GitHub (via your `gh` CLI session) or Linear (personal API key, stored in the OS keychain by the daemon) in Settings, and the project's open issues are imported into the backlog table when you open it. GitHub needs nothing further — the project's repository is the scope. Linear keys are account-wide, so each project picks its Linear team from the backlog toolbar; until you pick one, that project imports no Linear issues. Changing or clearing the team removes the rows the old team imported, leaving anything you wrote here and pushed to Linear alone. Creating a work item can target either tracker or stay local; it is the same form, the destination is just a chip. Mirrored rows show their remote id, link out to the issue, and refresh their status on open or via Sync. Starting a task from a backlog row links the two, so the row offers "Open task" from then on.

The backlog table is a plain server-driven table: one request object holds the page, the sort and the filters, and the daemon answers it. Status, Priority and Source filters and the title/body search now actually narrow the list (they previously wrote a value the table never read, so selecting one did nothing), sorting by status or priority follows workflow/urgency order instead of alphabetical, and paging keeps the current rows on screen while the next page loads. Paging back no longer leaves rows drawn but blank until you hover them, and the page indicator now matches the rows actually on screen instead of running ahead of them. Switching projects resets the view and refetches in one pass.
